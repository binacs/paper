# Pond: CXL-Based Memory Pooling Systems for Cloud Platforms

## TL;DR

Pond is the first CXL-based memory pooling system for public clouds that meets performance goals while cutting DRAM cost, using small pools (8-16 sockets) and ML-driven per-VM allocation of local vs. pool memory.

## Problem & Motivation

Public cloud providers must simultaneously satisfy stringent performance requirements and keep hardware costs low, and main memory is a key driver of both. Memory pooling can improve DRAM utilization and reduce cost, but conventional pooling approaches struggle to meet cloud-grade performance requirements, especially latency-sensitive same-NUMA-node behavior.

## Key Ideas

- Build on the CXL standard to provide load/store access to pooled memory.
- Analysis of cloud production traces shows pooling across only 8-16 sockets captures most of the benefit, enabling a small-pool design with low access latency.
- Use machine learning models to predict how much local and pool memory to allocate to each VM so that performance resembles same-NUMA-node memory.
- Combine small pools with accurate per-VM allocation prediction to meet cloud performance goals while reducing DRAM cost.

## System Design

- Pond is a memory pooling system built on CXL for load/store access to pool memory.
- It uses small pools spanning 8-16 sockets rather than large-scale pooling, keeping access latency low.
- Per-VM memory allocation is split between local memory and pool memory based on ML predictions.
- The ML models are trained to choose allocations that approximate same-NUMA-node memory performance.

## Evaluation

- Evaluated with 158 workloads.
- Compared against same-NUMA-node VM allocations as the performance reference.
- Headline result: DRAM costs reduced by 7% while performance stays within 1-5% of same-NUMA-node VM allocations.

## Takeaways

- Small CXL pools (8-16 sockets) are sufficient to capture most pooling benefits while preserving low latency.
- ML-based prediction of local vs. pool memory per VM is key to hiding pooling overhead from cloud workloads.
- Memory pooling can deliver meaningful DRAM cost savings without violating cloud performance requirements.
- Production trace analysis is a useful foundation for sizing pooling infrastructure.

## Open Questions

- How well do the ML allocation models generalize across workload shifts and new VM types?
- What are the failure, security, and isolation implications of CXL pool memory in multi-tenant clouds?
- How does Pond scale beyond 8-16 sockets, and what limits apply?
- How sensitive are the 7% cost savings and 1-5% performance overhead to specific workload mixes?
