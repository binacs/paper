# Pond: CXL-Based Memory Pooling Systems for Cloud Platforms

## TL;DR

Pond is a CXL-based memory pooling system for cloud platforms that reduces DRAM costs by 7% while keeping performance within 1-5% of same-NUMA-node VM allocations, using small pools and ML-driven memory allocation.

## Problem & Motivation

Public cloud providers need to meet stringent performance requirements at low hardware cost, and main memory is a key cost driver. Memory pooling can improve DRAM utilization and reduce costs, but existing pooling approaches struggle to meet cloud performance goals due to high access latency and unpredictable workload behavior.

## Key Ideas

- Use CXL for load/store access to pooled memory, enabling fine-grained, low-latency sharing.
- Analyze cloud production traces to show that pooling across only 8-16 sockets captures most benefits, enabling a small-pool design with low access latency.
- Train machine learning models to predict per-VM local vs. pool memory allocation that mimics same-NUMA-node performance.
- Combine small pools and accurate prediction to meet performance goals while reducing DRAM cost.

## System Design

- Pond builds on the CXL standard for load/store access to pool memory.
- It employs a small-pool design spanning 8-16 sockets to keep access latency low.
- For each VM, ML models predict how much memory should be allocated locally versus in the pool.
- The system likely includes a controller that manages pool memory and enforces allocations based on predictions.
- Data flow: VMs access local memory and pool memory via CXL; the controller monitors and adjusts allocations to maintain performance.

## Evaluation

- Evaluated with 158 workloads.
- Compared against same-NUMA-node VM allocations as the performance baseline.
- Headline results: reduces DRAM costs by 7% while performance stays within 1-5% of same-NUMA-node allocations.

## Takeaways

- Small memory pools (8-16 sockets) can capture most pooling benefits while keeping latency low.
- ML models can accurately predict local vs. pool memory allocation to approximate same-NUMA-node performance.
- CXL enables practical memory pooling for cloud platforms with modest cost savings and minimal performance impact.
- Production trace analysis is key to sizing pools and guiding design.

## Related Work

The abstract positions Pond as the first memory pooling system that both meets cloud performance goals and significantly reduces DRAM cost, contrasting with prior pooling approaches that likely fail to meet stringent performance requirements.

## Open Questions

- How well do the ML models generalize across different cloud workloads and hardware configurations?
- What are the overheads and failure modes of the CXL-based pool under real production conditions?
- Can the 7% cost reduction be improved with larger pools or different allocation strategies?
- How does Pond handle memory pressure, migration, and dynamic workload changes?
- What is the impact on tail latency and overall VM performance variability?
