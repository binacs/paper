# Order Matters: Sequence to sequence for sets

> **Why it matters:** It shows empirically that the order in which a seq2seq model reads its inputs and emits its outputs changes how well it trains, even when the chain-rule factorization says order should not matter. It then gives a permutation-invariant encoder for input sets (Read-Process-Write) and a training objective that searches over output orderings.

Version used: arXiv v4 (2016-02-23), read from the arXiv PDF.

## Problem

Seq2seq models factor P(Y|X) with the chain rule: an encoder RNN reads X in order and a decoder RNN emits Y in order. Many inputs and outputs are naturally *sets* (points to sort, variables of a graphical model). The paper asks:

1. If the input has no natural order, does the order you pick still matter? If it does, how do you build an encoder that ignores order?
2. If the output has no natural order, the chain rule holds for any permutation. Does the order still matter for learning? If it does, how do you find a good order?

The paper also notes (§3) that any sequence can be rewritten as a set of (element, index) tuples. So even for "real" sequences, order is a modeling choice and not something the data fixes.

## Core design

### Evidence that input order matters (§4.1)

The paper collects earlier results where reordering the input changed results: input reversal in machine translation and in constituency parsing, and sorting convex-hull points by angle. It attributes these effects to non-convex optimization and to the prior that the ordering imposes, not to the expressiveness of the factorization.

### Read-Process-Write (§4.2–4.3)

- **Read.** A small shared network embeds each input element x_i into a memory vector m_i. In the sorting experiment this network is a small MLP. No recurrence runs over the inputs, so nothing depends on input order.
- **Process.** An LSTM with no input and no output runs for T steps over the memories. At each step:
  - q_t = LSTM(q*_{t-1})
  - e_{i,t} = f(m_i, q_t)
  - a_{i,t} = softmax over i of e_{i,t}
  - r_t = Σ_i a_{i,t} m_i
  - q*_t = concat(q_t, r_t)

  Content-based attention is a weighted sum over memories, so r_t, and therefore the final state q*_T, does not change when the memories are shuffled. T is a compute knob: more steps mean more rounds of attention over the whole set.
- **Write.** An LSTM pointer network, conditioned on q*_T, emits outputs by pointing at memory slots one step at a time. Before each pointer step it can take a **glimpse**, an extra attention read over the memories.

### Evidence that output order matters (§5.1)

- **Language modeling (PTB).** The paper compares natural order, fully reversed order, and reversal within 3-word chunks.
- **Parsing.** It compares two linearizations of parse trees, depth-first and breadth-first.
- **Combinatorial problems.** Outputs such as sorting have large equivalence classes, with n! valid orderings. Restricting the model to one canonical order helped.
- **Star-shaped graphical models.** One "head" variable is unconditional and the rest depend on it. Two LSTMs were trained, one emitting the head first and one emitting it last. The result is reported only qualitatively. With large training sets, or with very peaky marginals, order did not matter. In the other cases, putting the head first was easier to learn.

### Searching over output orders during training (§5.2)

The objective (Eq. 9) maximizes, for each example, the log-likelihood of its *best* ordering:

θ* = argmax_θ Σ_i max_{π(X_i)} log p(Y_{π(X_i)} | X_i; θ)

The paper makes three practical points about this objective:

- **Lock-in.** A naive max chooses whichever ordering the random initialization happens to favor, and training stays on it.
- **Fix.** Pretrain with a uniform prior over orderings (sum instead of max) for a fixed number of steps. Then sample an ordering with probability proportional to p(Y_π|X), using left-to-right ancestral sampling. This costs a constant number of model evaluations, compared with factorial cost for exhaustive search.
- **Caveat.** Because the problem is non-convex, Eq. 9 is not guaranteed to beat plain maximum likelihood. The authors say this was not a problem in practice.

The test case is 5-gram modeling with no context (§5.2.1). Each 5-gram is turned into a set of (word, position) pairs, and the model must learn which order to emit them in. In "Easy", the training data uses two orderings. In "Hard", it uses all 5! orderings.

## Limitations

- **Small, synthetic benchmarks.** The set-input method is tested only on sorting up to N=15. At N=15 every configuration is at 10% accuracy or below (Table 1). The order-search method is tested only on 5-grams. No real-world set-input task is evaluated.
- **The process block is not consistently better.** With zero processing steps, Read-Process-Write does worse than Ptr-Net at N=5 (Table 1). At N=10, 10 steps with a glimpse score below 5 steps with a glimpse. The number of steps T is a hyperparameter the paper gives no rule for choosing.
- **Missing model details.** Hidden sizes and layer counts for the sorting models are not given in the text.
- **Qualitative graphical-model results.** The star-graph experiment (§5.1.4) reports no numbers or figure.
- **The order search is heuristic.** The search over orderings relies on pretraining and sampling to avoid lock-in. The authors say Eq. 9 has no guarantee of improving on maximum likelihood, and exhaustive search does not scale.
- **Recovering a known order is not discovering a new one.** In the 5-gram study the method finds the natural order again. The authors list finding previously unknown good orderings as future work.

## Relation to other systems

All of these systems are named in the paper. The comparisons are (Own analysis) based on what the paper describes.

- **Seq2seq (Sutskever et al. 2014; Cho et al. 2014).** These are the baseline factorization. Read-Process-Write keeps the decoder but replaces the recurrent encoder with per-element embeddings plus attention-only processing, so the encoder state does not depend on input order.
- **Pointer Networks (Vinyals et al. 2015a).** The write block is a Ptr-Net decoder, and Ptr-Net is the sorting baseline. The difference is the encoder: Ptr-Net runs an LSTM over the input sequence, which ties it to input order, while this paper uses an order-invariant attention loop.
- **RNNSearch / content attention (Bahdanau et al. 2015).** Both rely on the same mechanism, a softmax-weighted read over memories. This paper also uses attention as the *encoder* (the process block), not only as a decoder-side alignment.
- **Memory Networks (Weston et al. 2015) and Neural Turing Machines (Graves et al. 2014).** The process block has the same shape: a controller that reads a memory repeatedly over several hops. Here the memory is the embedded input set, and the controller takes no input of its own.
- **Recursive neural networks (Socher et al. 2010) and structured prediction (Bakir et al. 2007).** These assume a given structure such as a tree. This paper instead learns or searches for an ordering and keeps a flat chain-rule decoder.

## Takeaways for practice

All points in this section are (Own analysis), written for engineers building GPU training and inference systems.

- **Treat ordering as part of the data pipeline.** When a model consumes something without a natural order (a batch of requests, a set of devices, the nodes of a placement problem), the serialization you choose affects convergence. Fix it on purpose, record it in your config, and include it in ablations.
- **Choose between a permutation-invariant encoder and a canonical sort.** For set-shaped features, attention over per-element embeddings gives order invariance by construction. Sorting the input into a canonical order is the cheaper alternative the paper also shows working (§4.1, §5.1.3).
- **Processing steps are a compute knob with diminishing returns.** Each step is one attention pass over all N memories, so serving cost grows with T. Table 1 shows the gain flattening, and in some cells reversing, between 5 and 10 steps. Tune T against your latency budget instead of assuming more is better.
- **Watch for lock-in when the objective has a max over latent choices.** The paper's recipe (uniform-sum warm-up, then sampling in proportion to the model's own likelihood) applies to any objective with an inner max.
- **Output linearization is part of the model contract.** The depth-first vs breadth-first parsing gap (§5.1.2) also affects how often decoding produces invalid output, so keep it fixed across training and serving.
