# Relational recurrent neural networks

> **Why it matters:** It puts Transformer-style multi-head dot-product attention inside a recurrent cell, so a fixed set of memory slots can interact at every step, and shows this helps on tasks that need relational reasoning across time.

Version read: arXiv 1806.01822v2 (28 Jun 2018), from the arXiv PDF. The abs page lists an original submission on 5 Jun 2018 and v2 on 28 Jun 2018. The author list has ten names (Razvan Pascanu and Timothy Lillicrap follow the eight listed above).

## Problem

Memory-based networks such as LSTMs and memory-augmented networks are good at storing and retrieving information over long horizons. The paper asks whether they can also reason about how stored items relate to each other. Its argument: an LSTM packs everything into one hidden vector, which makes compartmentalisation hard, and slot-based memories (NTM, Memory Networks, DNC) compartmentalise but give slots little way to interact (Sec. 1, Sec. 2). The authors build a toy task, N-th Farthest, that needs relational reasoning over a sequence. They show that LSTM and DNC baselines fail on it, then propose the Relational Memory Core (RMC) and test it on program evaluation, reinforcement learning (Mini PacMan, BoxWorld) and word-level language modelling.

## Core design

### Memory as a matrix of slots (Sec. 3)

- The state is a matrix M with one row per memory slot.
- **Memory interaction (Eq. 1).** A_θ(M) = softmax(M W^q (M W^k)^T / √d_k) M W^v. Every slot attends to every other slot. The result is "a proposed update to M".
- **Writing the input (Eq. 2).** Keys and values come from the row-wise concatenation [M; x]. Queries come only from M, so the output M̃ keeps M's shape. Each step's input is therefore absorbed through the same attention that lets slots interact.
- **Multi-head.** Each head has its own projections. Head outputs are concatenated column-wise.
- **Row-wise MLP.** After attention, a shared row/memory-wise MLP with layer normalisation (g_ψ) is applied to each slot. The paper reports this worked best.

### Recurrence and gating (Sec. 3, Eqs. 3–9)

- Each memory row is treated as an LSTM cell state. The update is m_{i,t} = σ(f_{i,t} + b̃^f) ∘ m_{i,t-1} + σ(i_{i,t}) ∘ g_ψ(m̃_{i,t}).
- "In practice we did not find output gates necessary."
- **Unit gating** uses one gate per element. **Memory gating** uses one scalar gate per memory row, which turns the element-wise product into a scalar-vector multiplication.
- The attention-plus-MLP block can be stacked ("attention blocks"). The language-modelling sweep varies this.

### Scaling knobs (Sec. 3.3, App. A.1)

- Parameters are shared across rows, so "we can modify the number of memories without affecting the number of parameters".
- Total memory size is divided across memories (and across heads). The trade-off is between number of slots and slot width.
- App. A.1: "models with more but smaller memories are faster to run than those with fewer but larger memories".

### Tasks (Sec. 4, App. A)

- **N-th Farthest:** "What is the n^th farthest vector (in Euclidean distance) from vector m?" The model must "sort distance relations between vectors, and not the vectors themselves".
- **Program evaluation:** Learning to Execute (addition, control, full program) plus copy, reverse and double.
- **RL:** Mini PacMan with a 5×5 viewport or full observation; BoxWorld (App. A.3), a 14×14 grid seen through a 5×5 RGB viewport, trained with 100 actors and a GPU learner.
- **Language modelling:** WikiText-103, Project Gutenberg, GigaWord v5.

## Limitations

- **No causal claim.** Sec. 6: "we cannot necessarily make any concrete claims as to the causal influence of our design choices" on relational reasoning. Results are framed as evidence of improved function. Sec. 5.1 also says attention analysis is limited because "even after a single round of attention the memory can become highly distributed".
- **The LM result uses a single memory slot.** The best language model has 1 memory (App. A.4). The paper says this was driven by the large parameter count LM needs and "the inability to quickly run a model with both a large number of parameters and multiple memory slots", and that it does "not necessarily claim that a single memory slot is best" (Sec. 6). With one slot, the memory-memory interaction of Eq. 1 is degenerate; what remains is attention from the slot to [m; x], plus the row-wise MLP and gates (Own analysis).
- **Gains are on frequent words.** Sec. 5.4 says the overall perplexity drop comes from frequent words. In Table 3 the RMC's <1K-bucket perplexity (6.9e4) is worse than both LSTM rows.
- **Short-context bias.** Sec. 5.4 reports the RMC does well with few context words, while the LSTM "profited much more from a larger context".
- **No systems cost reported.** The paper gives no wall-clock, throughput, memory-footprint or parameter-count figures (Sec. 5.4 has no speed analysis). App. A.2 only says the top LSTMs "contained many more parameters" than the top RMCs.
- **Open questions.** Sec. 6 says the roles of slots versus heads are not yet understood, and suggests blending purely recurrent models with approaches that scale with time.

## Relation to other systems

All systems below are ones the paper names.

- **LSTM.** The RMC reuses LSTM-style input and forget gates but applies them per memory row, drops the output gate, and replaces the single hidden vector with a slot matrix whose rows interact through attention (Sec. 3).
- **DNC, NTM and Memory Networks.** These keep a slot memory but read and write through addressing rather than letting slots attend to each other. On N-th Farthest the DNC stays under 30% while the RMC reaches 91% (Sec. 5.1).
- **EntNet.** A gated multi-cell memory baseline on program evaluation. It is strong on Reverse and weak on Copy and Double in Table 1.
- **Transformer.** The RMC borrows multi-head dot-product attention. Sec. 6 contrasts it with attention over a growing buffer of past states, which has "serious scaling issues" when the number of timesteps is large or unbounded. The RMC instead attends over a fixed number of slots each step.
- **Relation Networks and non-local networks.** These compute relations between entities in one input. The RMC applies the same relational idea to memories accumulated across time (Sec. 2).
- **ConvLSTM, Quasi-RNN, Gated/Temporal CNN, LSTM + Hebbian Softmax.** Baselines for BoxWorld (73% vs 98%) and language modelling (Tables 2 and 3).

## Takeaways for practice

- **Per-step cost is fixed (Own analysis).** Attention runs over N slots plus one input row, not over the whole history. Inference state is a fixed-size N×d matrix per sequence, so the per-sequence memory footprint does not grow with sequence length, unlike the buffer-of-past-states attention that Sec. 6 says scales badly with many timesteps.
- **Training is still sequential (Own analysis).** The recurrence forces step-by-step computation inside each BPTT window (100 steps in App. A.4). There is no parallelism across time as in a Transformer over a full sequence. The paper's own report that the multi-slot, large-parameter LM could not be run "quickly" (Sec. 6) fits this.
- **Small kernels per step (Own analysis).** Each step is a short chain of small matmuls (projections over N+1 rows, softmax, MLP, gates). At small N, launch overhead and memory bandwidth will dominate. Fusing the whole cell, and batching many sequences, matters more than peak FLOPs.
- **Slots versus width is a performance knob.** Parameter count is independent of the number of slots (Sec. 3.3), and more-but-smaller memories ran faster in App. A.1. Profile before choosing a configuration, because the quality-optimal setting in LM (1 slot, 2500 units) was the opposite end.
- **Modest distributed recipe.** The LM result came from 6 synchronous P100s with a global batch of 384 (App. A.4). The RL results used a 100-actor, single-GPU-learner layout (App. A.3). Neither needed large-scale parallelism.
- **Check where aggregate gains come from (Own analysis).** The LM improvement is concentrated in frequent words while rare-word perplexity got worse (Table 3). When evaluating a model change on a platform, slice metrics by frequency or context length before trusting one headline number.
