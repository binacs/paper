# Neural Turing Machines

> **Why it matters:** It couples a neural controller to an external, explicitly addressed memory matrix through soft read and write heads that combine content- and location-based addressing, so the whole machine trains end to end by gradient descent.

These notes are based on arXiv v2 (stamp "arXiv:1410.5401v2 [cs.NE] 10 Dec 2014"), read from the arXiv PDF.

## Problem

Section 1 argues that machine learning has largely neglected flow control and external memory. RNNs are Turing-complete in principle (Siegelmann & Sontag, Sec. 1), but that does not make algorithms easy to learn. Section 2 adds the framing of working memory and the variable-binding critique of connectionism (Sec. 2.2). The goal is a network that learns simple algorithms (copying, sorting, associative recall) from input–output examples and generalises to longer sequences than it was trained on.

## Core design

**Architecture (Sec. 3).** A controller network talks to the outside world and to a memory matrix of `N` locations ("the number of memory locations"), each of size `M` ("the vector size at each location"). It reaches memory only through read and write heads. Every operation is differentiable, so controller, heads and addressing train jointly.

**Reading (Sec. 3.1, Eqs. 1–2).** A head produces a weighting `w_t` over the `N` locations; "all weightings are normalised" (each weight in [0, 1], summing to 1). The read vector is "a convex combination of the row-vectors" under that weighting.

**Writing: erase then add (Sec. 3.2, Eqs. 3–4).** Each write head emits an erase vector `e_t` with elements in (0, 1) and an add vector `a_t` of length `M`. Each row is first erased in proportion to its weight and `e_t`, then `a_t` is added in proportion to its weight. The split is inspired by LSTM's forget and input gates.

**Addressing pipeline (Sec. 3.3).** Each head builds its weighting in four stages from scalars and vectors the controller emits at every step:
1. *Content focus* (Sec. 3.3.1, Eqs. 5–6): a key `k_t` of length `M` is compared to every row by cosine similarity; a positive key strength `β_t` scales the scores before a softmax over locations. The paper relates this to content-addressing in Hopfield networks.
2. *Interpolation* (Eq. 7): a gate `g_t ∈ (0, 1)` blends the content weighting with the head's weighting from the previous step.
3. *Convolutional shift* (Eq. 8): a shift weighting `s_t`, a normalised distribution over allowed shifts, rotates the weighting by circular convolution ("if shifts between -1 and 1 are allowed, s_t has three elements").
4. *Sharpening* (Eq. 9): a scalar `γ_t ≥ 1` exponentiates and renormalises the weights.

Why location addressing: in an arithmetic example "the variables are addressed by location, not by content", and "providing location-based addressing as a primitive operation proved essential" for some generalisation (Sec. 3.3).

**Controller choice (Sec. 3.4).** An LSTM controller keeps internal state across steps besides the matrix. A feedforward controller is more interpretable but bounded by its head count: "With a single read head, it can perform only a unary transform on a single memory vector at each time-step".

**Training (Sec. 4.6).** RMSProp as in Graves (2013), momentum 0.9, elementwise gradient clipping to (−10, 10).

**Learned behaviour.** For Copy, the authors give pseudocode for what they believe the network does, starting with "initialise: move head to start location", and relying on relative shifts from the previous read and write weightings (Sec. 4.1). For Priority Sort, the write weightings "led us to hypothesise that it uses the priorities to determine the relative location of each write" (Sec. 4.5).

## Limitations

- **Synthetic tasks only.** All experiments are small synthetic sequence tasks with a 128 × 20 memory; no natural data or large memories are tested.
- **Fixed memory capacity bounds generalisation.** Footnote 2 of Sec. 4.1 names memory size as the limiting factor for longer copies; `N` is fixed up front. (Own analysis on the last point)
- **Dense addressing.** Content focus scores all `N` rows every step and every read and write touches every row, so cost grows linearly in `N` per head. (Own analysis)
- **Not optimal on N-Grams.** On Dynamic N-Grams the NTM "never quite reaches the optimum cost" (Sec. 4.4).
- **Interpretations are hypotheses.** The copy pseudocode and the priority-sort explanation are inferred from head weightings ("We believe...", "led us to hypothesise"; Secs. 4.1, 4.5).
- **Feedforward controller bottleneck.** Sections 3.4 and 4.5 note that the feedforward controller needs many heads, eight for Priority Sort, to do well.

## Relation to other systems

- **LSTM (Sec. 2.3, 3.2, 4).** Inspires the erase/add gating and serves as both a controller option and the baseline. The baseline has no addressable store and, per Table 3, many more parameters than the NTMs on most tasks.
- **Differentiable attention (Bahdanau et al.; Graves 2013; Sec. 2.3).** Named as precursors. NTM applies soft attention to a memory it also writes, and adds location-based iteration (gate, shift, sharpen) on top of content scoring. (Own analysis)
- **Hopfield networks (Sec. 3.3.1).** Content focus is related to Hopfield-style content addressing. NTM adds explicit, sharpenable location addressing on top of it. (Own analysis)
- **Turing machines and the von Neumann architecture (Abstract, Sec. 1).** "Unlike a Turing machine, an NTM is a differentiable computer": head movements are soft distributions, so the machine is learned, not programmed.
- **Hazy et al. (2006) working-memory model (Sec. 2.1).** The paper calls this "the most relevant to our work", but it lacks a "sophisticated notion of memory addressing", which is NTM's focus.

## Takeaways for practice

- **Dense soft addressing costs O(N) per head per step.** Each step is a similarity matmul, a softmax over `N` and a weighted sum over all rows, a memory-bound reduction worth fusing into one kernel. (Own analysis)
- **Writes put the memory into the autograd state.** Erase/add touches every row at every step, so backpropagation through time must keep or recompute each memory snapshot, and activation memory grows with sequence length × N × M per sample. Plan recomputation before scaling `N` or the sequence length. (Own analysis)
- **Location iteration is sequential.** The interpolation gate makes each weighting depend on the previous one, so head computation cannot be parallelised across time steps. Budget step latency accordingly. (Own analysis)
- **Structure versus parameter count.** Most NTM configurations use far fewer parameters than the LSTM baselines (Tables 1–3), so compare architectures on more than size. (Own analysis)
- **Test length generalisation explicitly.** The paper trains on lengths up to 20 and tests longer ones (Fig. 4). Keep length-extrapolation suites separate from in-distribution validation. (Own analysis)
