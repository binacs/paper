# A simple neural network module for relational reasoning

> **Why it matters:** It shows that one small shared MLP, applied to every pair of objects and summed, gives a network a built-in relational inductive bias, and it states the price plainly: the work grows quadratically with the number of objects.

Version read: arXiv 1706.01427v1 (5 Jun 2017), from both the arXiv PDF and the arXiv HTML rendering. Only one arXiv version is listed.

## Problem

The paper argues that relational reasoning is central to general intelligence. Symbolic approaches suffer from the symbol-grounding problem, and standard deep networks (CNNs, MLPs, LSTMs) struggle to learn sparse relational structure from data. The authors want a module that is "simple, plug-and-play, and [is] exclusively focused on flexible relational reasoning" (Sec. 1), can be bolted onto an existing perception front end, and trains end to end with gradient descent. To show the gap, they build Sort-of-CLEVR, a 2D dataset designed so that relational and non-relational questions can be scored separately (Sec. 3.2).

## Core design

### The RN equation (Sec. 2)

- RN(O) = f_φ( Σ_{i,j} g_θ(o_i, o_j) ), where O is a set of objects and f_φ and g_θ are MLPs. The output of g_θ is called a "relation".
- **Relations are built in, not learned.** The paper says the capacity to compute relations is baked into the architecture, much as CNNs bake in translation invariance and RNNs bake in sequential dependency.
- **Learning which relations exist.** By default all pairs are considered, so the network has to learn which relations matter. The paper notes that pairs can be restricted when that information is available.
- **Data efficiency through weight sharing.** One g_θ is shared across all pairs. An MLP fed all objects at once "must then learn and embed n² (where n is the number of objects) identical functions within its weight parameters", and "this quickly becomes intractable as the number of objects grows" (Sec. 2).
- **Set semantics.** The sum makes the output invariant to object order, so the input is treated as a set.

### Getting objects (Sec. 4)

- **Pixels.** A CNN takes a 128×128 image through four convolutional layers and produces k feature maps of size d×d. "Each of the d² k-dimensional cells in the d×d feature maps was tagged with an arbitrary coordinate indicating its relative spatial position" and is treated as an object. An object can therefore be background, a physical object, a texture or a conjunction of objects. The paper gives no numeric value for d.
- **Question conditioning.** Relations depend on the question, so the final state of a question LSTM, q, is fed into every pair: a = f_φ( Σ g_θ(o_i, o_j, q) ).
- **State descriptions.** Object attribute vectors are given directly, with the question embedding concatenated to each pair.
- **Text (bAbI).** Up to 20 support sentences are each encoded by a shared LSTM. The final state of each becomes an object, and a separate LSTM encodes the question.

### Training setup (Sec. 4, App. B)

- Ten synchronous workers update a central parameter server. Each uses mini-batches of 64, Adam and a learning rate of 2.5e-4.
- The paper says smaller models performed best.

## Limitations

- **Quadratic pair count.** The module considers every pair. The paper itself names "the otherwise quadratic complexity of the number of considered pairwise relations" as something future attention mechanisms should bound (Sec. 6). It reports no wall-clock, memory or throughput figures for the RN.
- **Objects are not discovered.** On pixels, an "object" is just a coordinate-tagged CNN cell, which may be background or a texture (Sec. 4). The RN reasons over whatever the front end emits.
- **The state-of-the-art claim is qualified.** Sec. 5.1 calls 95.5% "state-of-the-art performance on CLEVR". The same section reports a model at 96.9% that uses extra supervision on the functional programs [16].
- **Weak bAbI evaluation.** Two tasks are failed. The reported model was chosen on validation performance "using a single seed" (Sec. 5.4).
- **Failure modes.** CLEVR failures involve heavy occlusion or questions that need precise object positions (App. B, Table 2).
- **Synthetic benchmarks (Own analysis).** All four evaluations (CLEVR, Sort-of-CLEVR, bAbI, simulated mass-spring systems) are synthetic or templated, so transfer to cluttered real inputs is untested here.

## Relation to other systems

All systems here are ones the paper itself names.

- **Graph neural networks and Gated Graph Sequence Neural Networks.** The paper treats graphs as a natural structure for relations. It distinguishes the RN by the minimal oversight needed to produce its input objects. The RN is effectively a single round of message computation over a complete graph, followed by a global sum (Own analysis).
- **Interaction Networks.** These are described as closely related. The paper notes that an RN can also be given a list of only the relevant pairs.
- **Deep Sets.** Deep Sets reasons over sets but, per the paper, "does not explicitly reason about the relations of elements within sets". The RN keeps the sum-for-permutation-invariance trick and applies it to pairs rather than to single elements.
- **Stacked attention (CNN+LSTM+SA).** This is the strongest pixel baseline in Table 1. It is far behind on Compare Attribute, which the paper uses to argue that attention over image regions does not by itself give relational reasoning.
- **Module networks [14] and program induction/execution [16].** These compositional approaches need hand-designed modules or ground-truth programs. The RN gets comparable CLEVR results without program supervision.
- **Memory Networks, DNC, Sparse DNC, EntNet.** These are the jointly trained bAbI baselines. The RN matches DNC's task count with no external memory, by treating sentences as a set of objects.

## Takeaways for practice

- **Pairwise cost is quadratic by construction.** The paper applies one g_θ to all n² pairs and says the quadratic number of considered relations should be bounded, for example by attention that filters out unimportant pairs or by omitting pairs known to be unrelated (Sec. 2, Sec. 6). For pixel inputs, n is d², so the pair count grows with the fourth power of the feature-map side. Budget activation memory for n² rows of g_θ hidden state, not n (Own analysis).
- **The pairwise stage is one big batched MLP.** Every (o_i, o_j, q) row goes through the same weights with no data-dependent control flow, so it maps to large dense matrix multiplies, followed by a sum reduction before f_φ (Own analysis).
- **Factor the first layer.** The first linear layer of g_θ on the concatenation [o_i; o_j; q] splits into W_a·o_i + W_b·o_j + W_q·q. You can compute per-object projections once (O(n)) and broadcast-add them across pairs, rather than materialising and replicating q and each object n times (Own analysis).
- **Pruning pairs is the main lever.** The paper's own suggestions (attention, known-unrelated pairs) turn the dense n² batch into a sparse or variable-length one. Serving such a model then becomes a ragged-batching problem: padding versus packing pairs per example (Own analysis).
- **Order invariance simplifies sharding.** The sum over pairs is permutation-invariant, so pairs can be split across devices and partial sums reduced, without ordering constraints (Own analysis).
- **The training recipe is modest.** Synchronous data parallelism with 10 workers and a parameter server, mini-batch 64, Adam (App. B), and "smaller models performed best" (Sec. 4). The module's benefit came from structure, not scale.
- **Evaluate with replicas.** The bAbI result rests on a single seed. When comparing architectural changes on a platform, run multiple seeds before trusting small differences (Own analysis).
